WHY WEAVEFLOW

Explicit by design — inspectable by default

Agent workflow problems are not limited to whether a run completes. Control flow must be visible, state access must stay constrained, and failures must leave enough evidence to understand what happened.

01

Topology stays explicit

Define nodes, edges, routes, and state bindings in a serializable Graph instead of an implicit loop.

02

State has a contract

Use State Ports and explicit paths to catch invalid access and conflicting writes before execution.

03

Every run leaves evidence

Events, steps, checkpoints, and Artifacts make runtime decisions inspectable after they occur.

main.go 
package main

import (
  "github.com/dengzii/weaveflow"
  "github.com/dengzii/weaveflow/node"
  "github.com/dengzii/weaveflow/state"
)

func main() {
  workflow := weaveflow.NewGraph()
  conversation := state.Scope("agent", "conversation")

  input := node.NewUserInputNode(node.WithID("input"))
  message := node.NewConversationMessageNode(node.WithID("message"))
  message.InputPath = input.ValuePath
  message.ConversationPath = conversation

  answer := node.NewLLMTurnNode(node.WithID("answer"))
  answer.ConversationPath = conversation
  answer.OutputPath = state.Shared("final", "answer")

  _ = workflow.AddNode(input)
  _ = workflow.AddNode(message)
  _ = workflow.AddNode(answer)
  _ = workflow.AddEdge(input.ID(), message.ID())
  _ = workflow.AddEdge(message.ID(), answer.ID())
  _ = workflow.AddEdge(answer.ID(), weaveflow.EndNodeRef)
  _ = workflow.SetEntryPoint(input.ID())

  _, _ = weaveflow.NewRunner(workflow)
}
